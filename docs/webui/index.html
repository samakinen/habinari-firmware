This browser cannot talk to the board

Web Bluetooth is available in Chrome and Edge on Windows, macOS, Linux and ChromeOS, and in Chrome on Android. Safari and Firefox have not implemented it, and on iOS every browser uses Safari's engine — so an iPhone or iPad cannot run this page.

On any platform, tools/ble_config.py does the same job from a terminal.

Before you connect

The board advertises only while it is in programming mode. Hold the programming button for a second — the LED lights, and stays lit for as long as the window is open. A board that has never been commissioned puts itself into programming mode at boot.

An empty device chooser is almost always a board that is not in programming mode, rather than a fault.

Programming mode lapses on its own after 15 minutes by default.

The board wants pairing

Every characteristic needs an encrypted, authenticated link, so the first connection has to pair with the board's six-digit passkey.

The passkey is unique per device, derived from its eFuse root secret, and is printed on the device (or logged by the firmware on a bench). Your operating system raises the prompt, not this page:

  • Android, Windows, macOS — a system passkey dialog appears; type the six digits.
  • Linux — Chrome has no pairing agent. Pair once with bluetoothctl: agent KeyboardDisplay, default-agent, pair <address>, the six digits, then trust <address>. The bond is reused afterwards.

Bonds survive reboots. A factory reset erases them along with everything else.

Actions

Leaving programming mode stops advertising and takes an unaddressed Modbus board back off the bus — it is one state, so leaving it leaves all of it.

Commit marks the board commissioned and restarts it.

Factory reset

This erases all persisted state — commissioning, settings and Bluetooth bonds — and reboots. It cannot be undone.
